# 가지 클라우드 개선 체크리스트

> 원본: Google 문서 (3판). 이 파일은 저장소 작업용 사본입니다.
> 대상: https://gaji-cloud.vercel.app (편집기 v5)
> 작성: 2026-07-26 · 실제 브라우저 테스트 + 상용 마인드맵(XMind, MindMeister, Coggle, Whimsical, Miro, MindNode) 비교

## 작업 방식 — 먼저 읽어주세요

1. **한 번에 다 하지 말 것.** 아래 순서대로 단계를 끊어서 진행합니다. 0번(버그) → 확인·커밋 → 1군 → 확인·커밋 → 2군 → … 단계마다 브랜치를 따로 만듭니다.
2. **원인 추정을 그대로 믿지 말 것.** 이 문서의 「추정 원인」은 별도 단일 HTML 버전을 기준으로 쓴 것이라 현재 클라우드 코드와 다를 수 있습니다. 반드시 실제 코드에서 원인을 먼저 확인하고, **무엇이 원인이었는지 보고한 뒤** 수정합니다.
3. **작업 전 재현, 작업 후 검증.** 각 항목마다 (a) 재현 단계, (b) 수정 내용, (c) 검증 방법을 짧게 남깁니다.
4. **범위를 벗어난 리팩터링 금지.** 요청한 항목만 고칩니다.
5. 아래 항목 중 성격이 다른 것:
   - 0-4 — **미확인.** 재현부터 하고, 재현되지 않으면 그렇게 보고합니다.
   - 4장 접근 권한 점검 — 코드 수정이 아니라 **Supabase 설정 확인** 작업입니다.
   - 4장 항목 다수 — 스키마 변경이 필요하므로 마이그레이션 계획을 먼저 제시합니다.

## 0. 버그 — 먼저 고칠 것

### 0-1. 입력한 글자 앞부분이 사라짐 ★최우선

**증상**
노드를 더블클릭하고 바로 타이핑하면 앞쪽 글자가 통째로 유실됨.

**재현**
1. 노드 더블클릭
2. 1초 대기 후 「고양시 덕양구 주역 반경 500m 상권 재조사 및 경쟁점 가동률 비교 분석」 입력
3. 실제 저장된 값: 「500m 상권 재조사 및 경쟁점 가동률 비교 분석」 (앞 13글자 유실)

**추정 원인**
`startEdit()` 안의 재포커스 처리. `requestAnimationFrame` 안에서 조건부로 `selectNodeContents` + `removeAllRanges`를 다시 실행하는데, 이때 이미 입력된 글자가 전체 선택되면서 다음 입력에 덮여 사라짐.

**요구사항**
- 편집 진입 시 전체 선택은 **한 번만** 실행. 재포커스 로직은 사용자 입력이 한 글자라도 들어온 뒤에는 동작하지 않아야 함
- `compositionstart` 이후에는 어떤 경우에도 선택 범위를 건드리지 않을 것 (한글 IME 보호)
- 회귀 방지: 더블클릭 직후 0ms / 50ms / 500ms 시점에 각각 타이핑하는 테스트 추가

### 0-2. 수정 칸이 옆 노드를 덮음

**증상**
편집 중 노드가 글자 길이만큼 옆으로 늘어나는데 주변 노드는 제자리라 겹침.

**측정값**
편집 칸 left 204 → right 540, 중심 주제 노드 left 478 → right 602. 62px 겹침.

**요구사항 (택1, 앞쪽이 정석)**
- (A) 편집 중에도 레이아웃 재계산 — 입력할 때마다 폭·높이를 다시 재고 주변 노드를 밀어냄. 입력 중 화면이 요동치지 않도록 애니메이션은 짧게(120ms 이내)
- (B) 편집 칸을 최상위 레이어(z-index)로 띄우고 배경 완전 불투명 처리 + 그림자. 겹쳐도 글자는 안 섞임

**추가**
- 편집 칸이 화면 밖으로 나가면 자동으로 화면을 밀어 보이게 할 것
- 최대 폭 제한 후 자동 줄바꿈 (현재 편집 시 minWidth가 고정폭이라 짧은 글자도 칸이 큼)

### 0-3. 형제 주제가 반대편에 생김

**증상**
오른쪽 노드를 선택하고 Enter를 눌렀는데 새 노드가 화면 왼쪽에 생성됨.

**원인**
1단계 가지의 좌우 자동 균형 로직이 형제 추가 시에도 적용됨.

**요구사항**
- 형제 추가는 **원래 노드와 같은 쪽**에 생성 (side 상속)
- 좌우 균형은 사용자가 「화면 맞춤」이나 별도 「좌우 정리」를 누를 때만 적용
- 클라우드 저장/복원 시 side 값이 유실되지 않는지 확인 (JSON 왕복 검증)

### 0-4. 편집 취소 후 재진입 불가 ★미확인 — 재현부터

**증상**
Esc로 편집 취소 후 같은 노드를 더블클릭했으나 편집 모드로 안 들어감.

**확인할 것**
- 취소 시 노드 크기가 원복되며 클릭 좌표가 노드 밖으로 벗어난 것인지
- 아니면 `editing` 상태나 `lastTap` 값이 정리되지 않아 더블클릭 판정이 깨진 것인지
- `commitEdit()`에서 `lastTap = null` 초기화 여부 점검

### 0-5. 맵 이름이 전부 「중심 주제」

**증상**
대시보드에서 맵 이름이 중심 주제 텍스트를 따라가는데, 기본값 그대로면 전부 동일하게 보임.

**요구사항**
- 새 맵 생성 시 이름 입력 받기 (또는 생성 직후 중심 주제가 편집 상태로 시작)
- 대시보드 카드에서 이름 직접 수정 (더블클릭 또는 ⋯ 메뉴)
- 중심 주제와 맵 이름을 분리 저장하는 것도 검토

| **부모 노드 삽입** | XMind | 기존 노드 위에 상위 항목을 끼워넣기 |

| **관계선** | XMind, Lucidchart | 부모-자식이 아닌 임의의 두 노드를 화살표로 연결 + 라벨. 「A가 B에 영향」 표현 |

| **요약·경계** | XMind | 여러 형제를 묶어 괄호로 표시하거나 요약 노드 생성 |

## 3. 3군 — 마감 완성도

- **템플릿** — 주간 계획, 회의록, SWOT, 신규 출점 검토 같은 시작 틀
- **프레젠테이션 모드** — 가지를 하나씩 확대하며 발표
- **미니맵** — 큰 맵에서 현재 위치 표시
- **포커스 모드** — 특정 가지를 임시 루트로 삼아 파고들기
- **내보내기 확장** — 현재 PNG·MD. **PDF, SVG, OPML** 추가 (OPML은 다른 마인드맵 툴과 호환)
- **가져오기** — XMind, FreeMind, OPML 파일 읽기
- **스타일 옵션** — 노드별 글자 크기·굵기, 가지 선 모양(곡선/직선/꺾은선), 노드 테두리 모양
- **서식 복사** — 한 노드의 스타일을 다른 노드에 적용
- **인쇄** — 페이지 나눔 처리

## 4. 클라우드라서 필요한 것

- **동시 편집 충돌 감지** — 두 기기에서 같은 맵을 열면 나중 저장이 앞을 덮음. 최소한 「다른 곳에서 수정됨, 새로고침」 경고
- **저장 실패 표시** — 현재 「저장 중 / 저장됨」만 있음. 실패 시 **빨간 경고 + 재시도 버튼**. 저장된 줄 알고 창을 닫는 게 최악의 시나리오
- **오프라인 대응** — 연결 끊겨도 로컬에 쌓아두고 복구 시 전송
- **버전 기록** — 시점 되돌리기
- **휴지통** — 삭제 후 30일 보관
- **공유 권한 구분** — 보기 전용 / 편집 가능, 링크 만료
- **전체 내보내기** — 모든 맵 한 번에 백업
- **비로그인 읽기 전용 화면** — 링크 받은 사람이 로그인 벽을 만나면 공유 기능이 무의미. 이때 편집 버튼은 **숨김**(비활성화 아님)
- **접근 권한 점검** (코드 수정 아님 · Supabase 설정 확인) — 로그인 없이 `map.html?id=…` 접근 시 편집기 껍데기가 렌더링됨. 남의 맵 id로 데이터가 조회되는지, Supabase RLS가 켜져 있는지 확인 필요

## 5. 모바일

- 툴바 버튼 14개가 폰에서 여러 줄로 접히며 화면을 잠식 → 핵심 4~5개 + 「더보기」
- 폰에는 Tab/Enter 키가 없음 → 선택한 노드 옆에 **+ 버튼** 표시

- PWA 설정(manifest, 아이콘)으로 홈 화면 설치 지원

## 7. UI / UX

### 7-1. 급함 — 오해와 사고로 이어지는 것

**「이 폴더 공개」 용어 문제**
화면 어디에도 폴더를 만들거나 고르는 곳이 없는데 공유 문구에만 「폴더」가 등장함. 사용자가 공개 범위를 오해하면 그대로 사고.

- 내 맵 전체를 공개하는 것이면 → 「내 맵 전체를 링크로 공개」로 문구 변경
- 실제로 폴더 개념이 있으면 → 대시보드에 폴더 UI를 드러낼 것
- 공개 시 「무엇이 공개되는지」를 목록으로 미리 보여줄 것

**공개 상태 상시 표시**
토글을 켜도 페이지를 벗어나면 공개 중인지 알 수 없음. → 공개 상태면 헤더에 배지 상시 노출 (예: 「공개 중」 + 클릭 시 설정으로 이동)

**저장 상태 가시성**
현재 왼쪽 위 구석, 11px, 흐린 회색. 사용자 시선은 화면 가운데 노드에 있음. 이 위치·크기로는 저장 실패를 절대 알아채지 못함.

- 정상 저장: 지금처럼 조용하게 유지해도 무방
- **저장 실패·오프라인: 화면 상단 중앙에 눈에 띄는 배너 + 재시도 버튼**
- 저장되지 않은 변경이 있는 상태에서 탭을 닫으려 하면 브라우저 확인창

### 7-2. 편집기 화면

**툴바 정리 (버튼 13개가 한 줄)** — 성격이 다른 것이 같은 무게로 나열됨.
- 그룹 구분: 편집(하위·형제·색상·삭제) / 보기(화면 맞춤·야간) / 파일(열기·저장·이미지·마크다운)
- 파일 계열은 「⋯」 메뉴로 접기
- 우클릭 메뉴(1군) 구현 후 툴바를 더 축소

**버튼 비활성 상태 처리** — 현재 모든 버튼이 항상 활성. 눌러야만 안 된다는 걸 알게 됨.
- 중심 주제 선택 시 「삭제」 흐리게
- 되돌릴 이력 없으면 「되돌리기」 흐리게
- 선택된 노드 없을 때 편집 계열 전부 흐리게

**「삭제」 버튼의 위험도 표현** — 색상 버튼과 시각적으로 동일함. 하위 가지째 사라지는 동작인데 경고가 없음.
- 위험 동작 색상(빨강 계열) 적용
- 자식이 있는 노드 삭제 시 「하위 N개도 함께 삭제됩니다」 확인
- 삭제 후 「되돌리기」 안내 토스트

**「다시 실행」 버튼 추가** — 되돌리기만 있고 짝이 없음. 단축키를 아는 사람만 사용 가능.

**선택 상태와 편집 상태의 시각적 분리** — 현재 둘 다 파란 테두리 계열.
- 선택: 회색·중립 계열 테두리
- 편집: 파란 계열 + 배경 변화 (현행 유지)

**접기 버튼 크기** — 현재 18px. 마우스로도 작고 터치로는 거의 불가. → 최소 32px, 터치 대응 시 44px (시각적 원은 작게 두고 클릭 영역만 키워도 됨)

**하단 단축키 안내바** — 영구 노출되어 익숙해진 뒤엔 방해. → 닫기 버튼 제공, 또는 일정 사용 후 자동 숨김 + 「?」로 재호출

**버전 번호 노출** — 헤더의 「v5」는 개발용 표기. 완성 단계에서는 도움말 안으로 이동.

**첫 사용 안내** — 새 맵을 열면 「중심 주제」 하나만 있고 다음 행동을 알 수 없음. → 첫 노드 옆에 힌트 하나 (예: 「Tab을 눌러 가지를 뻗어보세요」), 한 번 수행하면 사라짐

### 7-3. 대시보드

**맵 카드 메뉴 없음** — 이름 바꾸기·복제·삭제를 하려면 맵을 열어야 함. → 카드에 「⋯」 메뉴 (이름 바꾸기 / 복제 / 사본 내려받기 / 삭제)

**정렬·검색 없음** — 맵이 20개가 되면 즉시 막힘. → 이름·수정일 정렬, 이름 검색

**「새로 만들기」 카드가 실제 맵보다 강조됨** — 진한 테두리로 시선을 먼저 가져감. → 점선 등 가벼운 처리로 낮추고, 실제 맵 카드를 주역으로

**맵이 없을 때 화면** — 빈 화면이 아니라 안내 + 「첫 맵 만들기」 버튼 + 템플릿 제안

**카드 썸네일** — 현재 축소 이미지가 작아 구분이 어려움. 중심 주제 텍스트를 크게 노출하거나 썸네일 품질 개선

### 7-4. 접근성

- 키보드만으로 전체 조작 가능한지 (툴바 Tab 이동, 포커스 링 표시)
- 색상만으로 정보를 전달하는 곳이 없는지 (가지 색 = 분류인데 색맹 대응)
- 명암비 확인 (특히 흐린 회색 텍스트, 야간 모드)
- 노드에 적절한 aria 속성 / 스크린리더 읽기 순서

## 권장 순서

각 단계는 브랜치를 나누고, 끝날 때마다 확인·커밋 후 다음으로 넘어갈 것.

**1단계 — 버그** · `fix/editor-bugs`
0-1(글자 유실) → 0-2(편집 칸 겹침) → 0-3(형제 방향) → 0-4(재현부터) → 0-5(맵 이름)

**2단계 — 사고 예방** · `fix/safety`
7-1 전체(폴더 용어·공개 배지·저장 실패 배너) + 4장의 저장 실패 처리 + 접근 권한 점검(Supabase 설정)

**3단계 — 조작감** · `feat/editing-basics`
우클릭 메뉴 → 검색 → 복사·붙여넣기 → 다중 선택 → 형제 순서 변경 → 전체 접기·펴기
(1군 항목. 우클릭 메뉴를 먼저 하면 이후 항목을 그 메뉴에 얹을 수 있음)

**4단계 — 화면 정리** · `feat/ui-polish`
7-2, 7-3 전체 (툴바 그룹·비활성 처리·삭제 경고·다시 실행·접기 버튼 크기·대시보드 카드 메뉴·정렬·빈 화면)

**5단계 — 표현력** · `feat/content`
노트 → 하이퍼링크 → 마크다운 붙여넣기 가져오기 → 아이콘·마커
(여기까지 하면 XMind 대신 쓰기에 무리가 없음)

**6단계 — 그 외**
2군 나머지(관계선·아웃라인·레이아웃), 3군, 5장 모바일, 6장 마감, 7-4 접근성

**별도 진행**
4장 클라우드 항목 중 스키마 변경이 필요한 것(버전 기록·휴지통·공유 권한)은 마이그레이션 계획을 먼저 세운 뒤 별도 브랜치에서.
